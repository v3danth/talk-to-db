1. People: the identity core

Everyone (student, professor, staff member) is one row in users. Its id is the admission number for students and the employee number for employees. The same value is the key everywhere else, under names like admn_no, emp_no, EMPNO, emp_id or admission_no.

  • users: login, role code auth_id (stu, emp, prj_emp, daily_emp, ...) and account status (A = active).
  • user_details (1:1): name, sex, category, DOB, email, dept_id → departments.
  • user_other_details (1:1): mobile, father/mother name, bank details. user_address (1:many): addresses with contact_no.
  • Roles: user_auth_types (1:many) → auth_types. One person can hold several roles.
  • Students extend with stu_academic (course, branch, current semester, enrollment year), stu_details (parent and alternate contacts), stu_other_details (guardian, Aadhaar, ABC id).
  • Employees extend with emp_basic_details. Its auth_id separates faculty (ft), non-faculty academic (nfta), non-faculty non-academic (nftn), project staff (prj_emp) and retired (retd_emp); designation → designations. Also faculty_details, emp_pay_details, emp_family_details.
  • Institute mail accounts: emaildata (students, by admission_no) and emaildata_emp (employees, by emp_id).

2. Programmes and subjects

A programme is a course + branch pair (course_branch → cs_courses, cs_branches), attached to a department through dept_course, which carries an aggr_id (the curriculum version).

  • Older scheme: course_structure (subjects per aggr_id and semester) → subject_mapping (offered in a session) with teachers in subject_mapping_des.
  • CBCS scheme: cbcs_subject_offered (+ _desc for faculty and components) per dept/course/branch/session, with cbcs_courses, cbcs_branches, cbcs_departments and credit rules in cbcs_credit_points_master.
  • NEP scheme (current batches) mirrors CBCS with nep_* tables. Much of it is used by a second application whose code isn't in this repo, so fewer joins are mined for it.

3. Semester registration and fees

Every semester each student files a registration form: reg_regular_form (or nep_reg_form for NEP batches). It has one row per student per session_year + session + semester, with approval columns hod_status / acad_status.

  • Hanging off form_id: fees (reg_regular_fee), electives (reg_regular_elective_opted), chosen courses (cbcs_stu_course, pre_stu_course).
  • Other forms: summer (reg_summer_form), other/backlog (reg_other_form), exam re-check (reg_exam_rc_form), honours/minor (hm_form).
  • Sections: stu_section_data by admn_no + session_year.
  • Fees paid: bank_fee_details, matched on admn_no + session_year + session. Fee structure: stu_fee_database_regular by course, semester and category.

4. Attendance, marks and results

  • Attendance: classes held go in class_engaged / cbcs_class_engaged (nep_class_engaged_course_wise for NEP), and absences in absent_table / cbcs_absent_table / nep_absent_table_course_wise. Practical groups use cbcs_prac_group_attendance.
  • Marks: cbcs_marks_upload (one upload per subject offering) with per-student rows in cbcs_marks_upload_description (marks_id). Older scheme: marks_master → subject_mapping. NEP: nep_marks_upload + _description.
  • Results: final_semwise_marks_foil_freezed is the published result, one row per student per semester (GPA, CGPA, status). Subject-wise grades are in final_semwise_marks_foil_desc_freezed (foil_id → id). The non-_freezed versions are working copies; _log tables are audit trails.

7. Admissions (applicants, before they become students)

Admissions has one family of tables per programme: adm_mtech_*, adm_phd_*, adm_phdef_*, adm_phdpt_*, adm_phdsd_*, adm_mba_*, adm_exmba_*, adm_exmtech_*, adm_ma_*, adm_bsced_*, adm_thyrmtech_*. All share the same shape, keyed by the applicant's registration_no, which is not a users.id:

  • _registration (applicant account) → _appl_ms (application) → _reg_appl_program (programme choices); _qulaification, _work_exp, _address, _doc (→ _doc_ms), _fellowship.
  • Outcome: _appl_selected; M.Tech counselling (COAP) rounds: adm_mtech_coap_*, adm_mtech_a_*. Masters: _program_ms, _degree_ms, _state_ms, _iit_ms.
  • JEE / JAM intake: adm_jee_*, adm_jam_*. Once admitted, a student gets an admission number and rows in users / stu_*.
